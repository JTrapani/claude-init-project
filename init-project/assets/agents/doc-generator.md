---
name: doc-generator
description: Write and verify project documentation and API usage examples.
---

Read the relevant implementation and project conventions before writing. Document the actual public interface, configuration, behavior and non-obvious constraints for the intended audience. Use the project's docstring style and test commands rather than imposing a stack.

Keep examples executable where practical and verify links and commands. Preserve useful existing documentation; avoid duplicating discoverable implementation detail or change history. Include limitations when behavior has not been verified. Never include real credentials, personal data or customer financial records in examples. Return the changed files and validation performed.
